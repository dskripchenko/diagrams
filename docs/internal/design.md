# @dskripchenko/diagrams — дизайн

Статус: принят 2026-10-24. Владелец решений — автор.

## Зачем

Документация в админке (laravel-admin) и в продуктах на ней (printable: вики
обеих панелей, публичные `/docs`) пишется в markdown. Схемы в ней сейчас —
картинки или ASCII. Mermaid решает задачу, но тянет за собой d3, dagre,
dompurify, khroma и ещё десяток пакетов (мегабайты), и у него была череда XSS
через подписи узлов.

Пакет рисует диаграммы из текста в синтаксисе Mermaid **без единой runtime-
зависимости** и без DOM: на входе строка, на выходе строка SVG. Это значит, что
он одинаково работает в браузере, в SSR и в Node-скрипте сборки.

## Решения автора (2026-10-24)

- Отдельный пакет, а не часть UI-кита. Кит получает `UidMarkdown` с реестром
  обработчиков блоков кода; ядро админки подключает диаграммы через реестр.
- Скоуп 1.0 — «базовый набор»: `flowchart` (включая `subgraph`), `sequenceDiagram`,
  `pie`, `gantt`, `stateDiagram-v2`. Остальное (class, ER, timeline, xychart,
  quadrant, Graphviz dot) — минорными релизами.

## Принципы

1. **Ноль зависимостей.** `dependencies` в `package.json` пуст и останется
   пустым. Dev-зависимости — только инструменты сборки и тестов.
2. **Безопасность по построению.** SVG собирается билдером, который экранирует
   каждый текст и каждое значение атрибута. Пользовательский текст никогда не
   попадает в разметку без экранирования; HTML в подписях не поддерживается
   (показывается как текст). Ссылки (`click … href`) — только http(s), mailto,
   относительные и якоря, как в markdown-рендерере ядра.
3. **Объявленное подмножество.** Поддерживаемый синтаксис описан в доках
   поштучно. Неизвестная конструкция — ошибка `DiagramError` с номером строки и
   колонки, а не молчаливо кривая картинка. Потребитель (UidMarkdown) на ошибке
   показывает исходник как код и сообщение.
4. **Детерминизм.** Одинаковый вход и одинаковый измеритель текста дают
   байт-в-байт одинаковый SVG. Это условие для эталонных тестов.
5. **Темизация через CSS.** Цвета и шрифт — CSS-переменные `--dg-*` с
   дефолтами внутри SVG. Хост переопределяет их снаружи (кит маппит свои токены),
   тёмная тема — переопределением тех же переменных.

## Публичный API

```ts
import { render, parse, detect, DiagramError } from '@dskripchenko/diagrams'

const { svg, width, height, type } = render(source, {
  measureText,   // (text, font) => { width, height }; по умолчанию — см. ниже
  idPrefix,      // префикс id внутри SVG (маркеры стрелок, clipPath); уникален на странице
  title,         // <title> для доступности; иначе берётся из `title` диаграммы или типа
})

detect(source) // 'flowchart' | 'sequence' | 'pie' | 'gantt' | 'state' | null
parse(source)  // AST без раскладки — для инструментов и тестов
```

Отдельные точки входа по типам (`@dskripchenko/diagrams/flowchart` и т. д.)
для тех, кому нужен один тип и минимальный размер; `render` собирает все.

### Измерение текста

Раскладка зависит от ширины подписей. Интерфейс `TextMeasurer` подключаемый:

- в браузере по умолчанию — `canvas.measureText` (через `OffscreenCanvas`,
  если есть, иначе скрытый `<canvas>`), с кешем;
- без DOM — таблица средних ширин символов для sans-serif (латиница, кириллица,
  цифры, пунктуация; CJK — полная ширина). Ошибка оценки ±10% — допустимо
  для SSR, узлы получают запас по паддингу;
- в тестах — детерминированный измеритель из того же модуля.

## Архитектура

```
src/
  core/
    svg.ts        билдер SVG: элементы, экранирование, сериализация
    text.ts       TextMeasurer, перенос строк, многострочные подписи
    theme.ts      CSS-переменные, стили внутри SVG
    errors.ts     DiagramError (line, column, message, hint)
    scanner.ts    построчный сканер с позициями, общие токены
    geometry.ts   точки, прямоугольники, пересечение луча с фигурой, сглаживание
    shapes.ts     фигуры узлов: rect, round, stadium, circle, rhombus, hexagon, …
    markers.ts    наконечники стрелок
  layout/
    layered/      послойная раскладка (Sugiyama) с кластерами
  diagrams/
    flowchart/    parser.ts, layout.ts, render.ts
    state/        parser.ts → граф → layered
    sequence/     parser.ts, layout.ts (своя линейная раскладка), render.ts
    pie/
    gantt/
  index.ts        render/parse/detect, реестр типов
```

### Послойная раскладка (`layout/layered`)

Самая трудная часть; на ней стоят flowchart и state.

1. **Удаление циклов** — DFS, обратные рёбра разворачиваются (и помечаются,
   чтобы стрелка рисовалась в исходную сторону).
2. **Ранжирование** — longest-path как старт, затем network simplex для
   минимизации суммарной длины рёбер. Учитывает `minlen` (длина `---->`).
3. **Нормализация** — длинные рёбра разбиваются фиктивными узлами по слоям.
4. **Упорядочивание в слоях** — барицентрическая эвристика с проходами вниз и
   вверх + transpose для уменьшения пересечений, ограниченное число итераций.
   Кластеры (subgraph) упорядочиваются как единое целое: узлы кластера в слое
   идут подряд (рекурсивно для вложенных).
5. **Координаты** — Brandes–Köpf (четыре выравнивания, медиана), с учётом
   ширины узлов и отступов кластеров.
6. **Кластеры** — рамки по границам содержимого с паддингом и местом под
   заголовок. Рёбра к/от кластера (`A --> sub1`) привязываются к рамке.
7. **Маршруты рёбер** — ломаная через фиктивные узлы, сглаживание (cubic
   Bézier / monotone), обрезка концов по контуру фигуры, место под подпись
   ребра (подпись — фиктивный узел на среднем слое).

Направления `TB/TD/BT/LR/RL` — раскладка всегда сверху вниз, затем поворот/
отражение координат, ширина и высота узлов меняются местами для LR/RL.

Ограничения ради предсказуемого времени: ≤ 500 узлов и ≤ 2000 рёбер на
диаграмму (дальше — `DiagramError` с понятным текстом), итерации ordering
ограничены.

## Поддерживаемый синтаксис 1.0

### flowchart / graph

- Заголовок: `flowchart TD|TB|BT|LR|RL`, `graph …`.
- Узлы: `id`, `id[текст]`, `id(текст)`, `id([текст])`, `id[[текст]]`,
  `id[(текст)]`, `id((текст))`, `id>текст]`, `id{текст}`, `id{{текст}}`,
  `id[/текст/]`, `id[\текст\]`, `id[/текст\]`, `id[\текст/]`, `id(((текст)))`.
  Текст в кавычках `"…"`, переносы `<br>` (единственный «тег», понимается как
  перенос строки), markdown-строки ``"`**жирный**`"`` — жирный/курсив.
- Рёбра: `-->`, `---`, `-.->`, `-.-`, `==>`, `===`, `--o`, `--x`, `<-->`,
  `o--o`, `x--x`, удлинение (`--->`, `-..->`, `===>`), подписи `-- текст -->`
  и `-->|текст|`, цепочки `A --> B --> C`, `A & B --> C & D`, `~~~` (невидимое).
- `subgraph id [заголовок] … end`, вложенные, `direction` внутри subgraph,
  рёбра к subgraph.
- `classDef`, `class`, `:::класс`, `style id …`, `linkStyle n …` — только
  безопасный набор свойств: fill, stroke, stroke-width, stroke-dasharray, color,
  font-weight, font-style. Значения валидируются.
- `click id href "url" "tooltip"` — ссылки (с фильтром схем). `click id callback`
  — не поддерживается (JS из текста не исполняем).
- Комментарии `%%`, директивы `%%{init: …}%%` — игнорируются с предупреждением.

### stateDiagram-v2

`[*]`, состояния `s1`, `s1 : описание`, `state "текст" as s1`, переходы
`s1 --> s2 : событие`, составные `state s1 { … }`, `<<choice>>`, `<<fork>>`,
`<<join>>`, `note left|right of s1 … end note`, `direction`, `--` (конкурентные
области) — 1.0 рисует области как разделённый пунктиром кластер.

### sequenceDiagram

`participant`/`actor` с `as`-алиасами, `autonumber`, сообщения `->`, `-->`,
`->>`, `-->>`, `-x`, `--x`, `-)`, `--)`, активации `+`/`-` и
`activate`/`deactivate`, `note left of|right of|over A,B`, блоки `loop`, `alt`/
`else`, `opt`, `par`/`and`, `critical`/`option`, `break`, `rect rgb(...)`,
`box`, `create`/`destroy` participant.

### pie

`pie [showData]`, `title …`, `"метка" : число`. Подписи с процентами, легенда.

### gantt

`title`, `dateFormat` (подмножество: `YYYY-MM-DD`, `YYYY-MM-DD HH:mm`, `HH:mm`),
`axisFormat` (подмножество strftime), `section`, задачи с `done`/`active`/`crit`/
`milestone`, id, `after id…`, длительности `Nd`/`Nh`/`Nw`/`Nm`, даты начала/
конца, `excludes weekends` и конкретные даты, `todayMarker off`.

## Тестирование

- Unit: парсеры (позиции ошибок), каждая фаза раскладки отдельно (инварианты:
  нет пересечений узлов, рёбра идут по слоям, кластеры содержат свои узлы).
- Эталоны: корпус `tests/fixtures/*.mmd` → SVG с детерминированным
  измерителем; снапшоты лежат в репозитории, изменение — осознанное.
- Браузер: Playwright рендерит галерею корпуса со стандартным измерителем
  (canvas) и сравнивает скриншоты; плюс проверка на отсутствие наложений через
  `getBBox`. jsdom геометрию не считает — без браузерного прогона релиза нет.
- Безопасность: фаззинг подписей (`<script>`, `"><svg onload=`, `javascript:`)
  → в SVG нет ни одного неэкранированного `<` из пользовательского текста.
- Производительность: 500 узлов flowchart < 200 мс в Node.
