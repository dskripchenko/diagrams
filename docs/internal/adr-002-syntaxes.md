# ADR-002. Несколько синтаксисов: PlantUML, DOT, D2, Structurizr, DBML, Wardley

Статус: принят 2026-10-30. Владелец решений — автор.

## Контекст

Пакет рисует 11 типов диаграмм в синтаксисе Mermaid. Архитекторы и аналитики
пишут схемы и в других текстовых форматах: прежде всего PlantUML (самый
распространённый после draw.io формат схем в Confluence), а ещё Graphviz DOT,
D2, Structurizr DSL (C4 как модель), DBML (схема БД), DSL карт Уордли.
Решение автора: не тянуть их реализации (PlantUML — Java, Graphviz — C,
D2 — Go), а читать эти синтаксисы сами — так же, как Mermaid.

Форматы «модель с координатами» (BPMN 2.0 / DMN, draw.io) сюда не входят:
это файлы из чужих редакторов, им нужны точный разбор XML, сохранение без
потерь и визуальный редактор. Они — отдельные пакеты `@dskripchenko/bpmn` и
`@dskripchenko/drawio`. AsyncAPI — в `@dskripchenko/openapi`; нотации EPC,
DFD, IDEF0 — палитры `@dskripchenko/flow`; шаблоны воркшопов — `board`.
ArchiMate исключён: товарный знак The Open Group, заявлять поддержку можно
только по их лицензии.

## Решения

1. **Одна библиотека, несколько синтаксисов.** Ядро (SVG-билдер, измерение
   текста, фигуры, маркеры, темы, раскладка по слоям) общее. Каждый синтаксис —
   свой разборщик в `src/<синтаксис>/`, который строит **существующие модели**
   там, где они подходят, и новые — только где нет подходящей:
   - PlantUML sequence → модель `sequence`;
   - PlantUML use case / component / deployment / object («описательные»
     диаграммы) и activity → модель `flowchart` (раскладка по слоям, вложенные
     контейнеры);
   - PlantUML class → `class`, state → `state`, ER (IE) → `er`,
     mindmap → `mindmap`, gantt → `gantt`, C4-PlantUML → `c4`;
   - DBML → `er`; Structurizr DSL → `c4`; DOT и D2 → `flowchart`;
   - новые модели: timing и Salt (PlantUML), карта Уордли.
   Рендереры расширяются тем, чего им не хватало (фигуры UML и инфраструктуры,
   рамки контейнеров, наконечники, участники sequence с иконками, разделители
   и задержки), и этим сразу пользуется и Mermaid.
2. **Определение синтаксиса.** `render(source)` смотрит на первую значимую
   строку: `@startuml` / `@startmindmap` / `@startgantt` / `@startsalt` /
   `@startjson` — PlantUML; `digraph` / `graph` / `strict` с `{` — DOT; и т. д.
   Явный выбор — `render(source, { syntax: 'plantuml' })`. Тип диаграммы
   внутри PlantUML определяется по содержимому, как это делает сам PlantUML
   (сообщения между участниками — sequence, `:действие;` — activity,
   `(вариант)` / `actor` — use case, …).
3. **Одна точка входа.** Пакет помечен `sideEffects: false`, разборщики —
   именованные модули: сборщик потребителя и так отбрасывает неиспользуемое.
   Отдельные точки входа (`/plantuml`, `/dot`) добавим, только если размер
   станет мешать на практике.
4. **Объявленное подмножество.** Как и для Mermaid: поддерживаемое описано в
   доках поштучно; неизвестное — `DiagramError` со строкой и колонкой.
   `skinparam`, `!theme` и прочее оформление PlantUML пропускаются (цвета —
   из тем пакета), `!include` и препроцессор с переменными — ошибка с
   объяснением (файлов и сети у рендерера нет). Цвета у элементов
   (`#red`, `#FFAA00`) поддерживаются через общие правила стилей.
5. **Принципы пакета не меняются:** ноль runtime-зависимостей, без DOM,
   экранирование всего пользовательского текста, детерминированный вывод.
6. **Название.** Пакет остаётся `@dskripchenko/diagrams`; описание — «схемы
   из текста: Mermaid, PlantUML, …». Синтаксисы называются по их авторам
   («синтаксис PlantUML»), код и тексты их реализаций не используются.

## Порядок

1. PlantUML, часть 1: препроцессор, sequence, use case, component,
   deployment, activity (без дорожек).
2. PlantUML, часть 2: class, state, object, ER (IE), дорожки activity.
3. PlantUML, часть 3: C4-PlantUML, mindmap, gantt, timing, Salt.
4. Остальной Mermaid: journey, quadrantChart, requirementDiagram,
   architecture-beta, block-beta, sankey, gitGraph, kanban.
5. DOT, D2, DBML, Structurizr DSL, карты Уордли.

Каждая часть — минорный релиз; потребители (embed, плагин Confluence, ядро
админки) получают новые языки блоков без своих изменений, кроме списка
языков ```plantuml, ```dot, … в реестре блоков embed.
